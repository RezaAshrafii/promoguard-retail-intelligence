# API and dashboard operating guide

Phase 4 exposes the deterministic PromoGuard domain services through typed HTTP contracts and a
Persian reviewer-facing dashboard. Neither adapter implements analytical formulas; calculations
remain in `src/promoguard`.

## Start from a fresh checkout

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,dashboard]"
```

The real public workbook must first be transformed according to `docs/data-acquisition.md`. Raw
and processed data are intentionally excluded from Git.

## HTTP API

```powershell
uvicorn apps.api.main:app --reload
```

OpenAPI UI: `http://127.0.0.1:8000/docs`

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Service and package health |
| `POST` | `/v1/panels/validate` | Validate a local canonical panel path |
| `POST` | `/v1/panels/validate-upload` | Validate a bounded CSV upload |
| `POST` | `/v1/promotions` | Detect and return a bounded event list |
| `POST` | `/v1/audits` | Audit an explicit or deterministically selected event |

Example local validation:

```powershell
$body = @{
  input_path = "data/processed/breakfast-at-the-frat"
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8000/v1/panels/validate" `
  -ContentType "application/json" `
  -Body $body
```

An explicit audit key requires all three fields together: `store_id`, `upc`, and `start_date`.
Omitting all three applies the documented representative-event rule. `unit_margin` is optional and
must be a positive, approved business input; otherwise the API refuses to calculate profit.

Boundary behavior:

- missing local path: `404`;
- malformed local CSV: `400`;
- invalid canonical panel: `422` before analysis;
- empty upload: `400`;
- upload over 120 MiB: `413`;
- partial event key or invalid request type: `422` generated by Pydantic/FastAPI.

The 120 MiB and one-million-row limits are application safety limits, not statistical claims.

## Streamlit dashboard

```powershell
streamlit run apps/dashboard/app.py
```

The flow is:

1. choose the real local panel or a canonical CSV upload;
2. inspect validity, row count, series count, promotion rows, date range, and quality failures;
3. select one detected promotion episode;
4. optionally enter a real unit-margin scenario;
5. run the audit and inspect decision, intervals, windows, warnings, assumptions, and evidence;
6. download the typed JSON result.

The interface states that the result is observational and does not identify a causal effect. A
reviewer can see the limitation before selecting data and again beside the result.

## Scripted evidence path

```powershell
python -m demo.phase4_smoke
```

The script exercises the HTTP boundary against the locally processed public data and writes
`reports/phase-04/demo-smoke.json`. It does not replace integration tests; it proves that the
full-size real panel can pass the same application path used by a reviewer.
