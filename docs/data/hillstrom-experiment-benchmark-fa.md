# داده و روش ارزیابی آزمایش Hillstrom

## کاربرد در PromoGuard

این داده یک مسیر مستقل برای سنجش کمپین‌های دارای تخصیص تصادفی می‌دهد. هر ردیف یک مشتریِ تخصیص‌یافته است و ستون `segment` نشان می‌دهد ایمیل محصولات مردانه، ایمیل محصولات زنانه یا هیچ ایمیلی دریافت کرده است. خرید، بازدید و مبلغ خرید در دو هفتهٔ پس از ارسال ثبت شده‌اند.

Hillstrom جای دادهٔ هفتگی فروشگاه و کالا را نمی‌گیرد. از این داده برای نمایش و اعتبارسنجی روش ارزیابی آزمایش کنترل‌شده استفاده می‌کنیم؛ ممیزی مشاهده‌ای خرده‌فروشی همچنان مسیر جداگانه‌ای دارد.

## منبع، دسترسی و نگهداری

- صفحهٔ ناشر: <https://blog.minethatdata.com/2008/03/minethatdata-e-mail-analytics-and-data.html>
- پیوند مستقیم CSV: <http://www.minethatdata.com/Kevin_Hillstrom_MineThatData_E-MailAnalytics_DataMiningChallenge_2008.03.20.csv>
- زمان ثبت نسخهٔ محلی: 2026-10-04.
- SHA-256 نسخهٔ دریافت‌شده: `0e5893329d8b93cefecc571777672028290ab69865718020c78c7284f291aece`.
- اندازه: 3,964,977 بایت؛ 64,000 ردیف و 12 ستون.
- صفحهٔ ناشر مجوز بازتوزیع مشخصی را درج نمی‌کند؛ نسخهٔ خام داخل `data/raw/` می‌ماند، در Git قرار نمی‌گیرد و پروژه فقط نتیجه‌های تجمیعی را ذخیره می‌کند.
- فایل شناسهٔ مستقیم مشتری ندارد. 6,562 ردیف کاملاً مشابه مشاهده شد؛ حذف نشدند، چون افراد متفاوت ممکن است ویژگی و نتیجهٔ یکسان داشته باشند.

## قرارداد تحلیل

- واحد تخصیص: مشتری.
- گروه کنترل: `No E-Mail`.
- گروه‌های کمپین: `Mens E-Mail` و `Womens E-Mail`.
- پیامد اصلی پیش‌فرض: `spend`، یعنی مبلغ ناخالص خرید ثبت‌شده به‌ازای هر مشتری در بازهٔ دو هفته‌ای.
- پیامدهای `conversion` و `visit` فقط برای توصیف کنار نتیجه می‌آیند؛ تا زمانی که از پیش یکی را پیامد اصلی نکنیم، از بین آن‌ها برنده انتخاب نمی‌کنیم.
- اثر بر مبنای همهٔ افراد تخصیص‌یافته محاسبه می‌شود؛ بازکردن ایمیل یا بازدید پس از ارسال شرط ورود به تحلیل نیست.
- هر کمپین با گروه کنترل و دو نسخهٔ ایمیل مستقیماً با یکدیگر مقایسه می‌شوند. بازه‌ها 95٪ پوشش هم‌زمان با تصحیح Bonferroni برای هر سه مقایسه دارند.
- بازهٔ اصلی از خطای استاندارد Welch با واریانس جداگانهٔ گروه‌ها و تقریب نرمال استفاده می‌کند؛ محاسبه بر میانگین پیامد در تخصیص تصادفی تکیه دارد.
- زیر 1,000 نفر در هر بازوی یک مقایسه، موتور اندازهٔ اثر و بازه را نشان می‌دهد ولی تصمیم مدیریتی را `insufficient_sample` می‌کند.

## تفسیر تصمیم

وقتی حداقل اثر تجاری تعیین نشده باشد، خروجی فقط می‌گوید بازهٔ هم‌زمان کاملاً بالای صفر، کاملاً پایین صفر، یا شامل صفر است. این «موفقیت تجاری» نیست. گروه‌های کوچک‌تر از حداقل از پیش تعیین‌شده حکم مدیریتی نمی‌گیرند.

اگر مدیر محصول حداقل اثر موردنیاز را تعیین کند، موتور بررسی می‌کند آیا کل بازه بالاتر از آن هدف، پایین‌تر از آن، یا هم‌پوشان با آن است. آستانه باید با واحد پیامد و هزینه‌های واقعی سازگار باشد و منبع آن ثبت شود. برای این فایل، `spend` درآمد ناخالص است؛ هزینهٔ ایمیل، تخفیف و حاشیهٔ سود در دسترس نیست، پس حکم سودآوری ممکن نیست.

## فرمان‌ها

```powershell
python tools/download_hillstrom.py
python -m promoguard.cli experiment-evaluate `
  --input data/raw/hillstrom/hillstrom-email-analytics-2008.csv `
  --output reports/hillstrom
```

برای آزمون آستانهٔ نمونه، مقدار آن را در همان واحد هر مشتری وارد کن. نمونهٔ زیر فقط رفتار فنی را نشان می‌دهد و آستانهٔ پیشنهادی کسب‌وکار نیست:

```powershell
python -m promoguard.cli experiment-evaluate `
  --input data/raw/hillstrom/hillstrom-email-analytics-2008.csv `
  --output reports/hillstrom-threshold-check `
  --primary-outcome spend `
  --minimum-effect-per-person 0.25
```

## محدودیت‌ها

- این آزمایش دربارهٔ ایمیل بازاریابی است، نه تخفیف قیمت، موجودی یا فروش هفتگی کالا.
- «تصادفی‌سازی» طبق توصیف ناشر پذیرفته شده است؛ بررسی تعادل ویژگی‌های پیش از کمپین می‌تواند خطاهای آشکار را نشان دهد، اما به‌تنهایی تصادفی‌سازی را ثابت نمی‌کند.
- درآمد افزوده با سود یکی نیست. هزینهٔ اجرا، حاشیهٔ سود و اثرهای بلندمدت وجود ندارند.
- دادهٔ سال 2008 است و نمایندهٔ بازار ایران یا رفتار فعلی مشتریان نیست.
- نتایج روی این benchmark درستی پیاده‌سازی و نمایش روش را ارزیابی می‌کنند؛ تقاضای تجاری، تمایل به پرداخت یا اثر یک مشتری PromoGuard را اثبات نمی‌کنند.
