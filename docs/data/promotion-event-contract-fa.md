# قرارداد رویداد پروموشن — نسخهٔ `promotion-event-contract.v1`

این قرارداد می‌گوید هر کمپین کدام کالاها را، در چه بازه‌ای، با چه مکانیزمی، در کدام کانال و
منطقه درگیر کرده است. هدف این است که «تخفیف» از یک پرچم مبهم به یک رویداد قابل پیگیری تبدیل شود.

## فیلدهای هر کمپین

| فیلد | معنی |
|---|---|
| `promotion_id` | شناسهٔ یکتای کمپین در فایل رویدادها |
| `sku_ids` | یک یا چند شناسهٔ کالای درگیر |
| `start_date`, `end_date` | روز شروع و پایان، با احتساب هر دو روز |
| `discount_type` | نوع سازوکار: درصدی، مبلغ ثابت، چندتایی، باندل، کوپن، نمایش، جایگاه یا سایر |
| `discount_depth` | مقدار تخفیف برای تخفیف درصدی یا مبلغ ثابت؛ برای سازوکار غیرقیمتی خالی می‌ماند |
| `discount_depth_unit` | `fraction` برای درصد به شکل اعشاری، `currency_per_unit` برای مبلغ، یا `not_reported` |
| `currency` | کد سه‌حرفی ارز، فقط برای کاهش مبلغ ثابت |
| `channel` | کانالی که کمپین در آن اجرا شده |
| `region` | منطقهٔ اجرای کمپین |

درصد ۱۵٪ به شکل `0.15` ثبت می‌شود. برای کاهش مبلغ ثابت، مقدار باید مثبت و همراه کد ارز باشد.
برای کمپین‌هایی مثل باندل یا نمایش که عمق قیمت واحد ندارند، مقدار عمق ثبت نمی‌شود و واحد
`not_reported` است. درصد و مبلغ با یکدیگر مخلوط نمی‌شوند.

## قواعد اعتبارسنجی

- شناسهٔ کمپین و SKU خالی پذیرفته نمی‌شوند؛ فهرست SKU یک کمپین نباید تکراری باشد.
- `end_date` نباید پیش از `start_date` باشد.
- `promotion_id` در یک registry یکتا است.
- عمق درصدی باید در بازهٔ بزرگ‌تر از صفر تا ۱ باشد.
- کاهش مبلغ ثابت به مقدار مثبت، واحد مبلغ و ارز نیاز دارد.
- مکانیزم‌های غیرقیمتی نباید عمق یا ارز ساختگی بگیرند.
- فیلد اضافه و تعریف‌نشده رد می‌شود تا خطای نام‌گذاری پنهان نماند.

نمونهٔ قابل ویرایش در `data_contracts/promotion_event_registry.v1.example.json` قرار دارد.
در حال حاضر این قرارداد ساختار رویداد را اعتبارسنجی می‌کند؛ هنوز آن را به ردیف‌های فروش وصل
نمی‌کند و به‌تنهایی هم‌خوری، post-promotion یا اثر اقتصادی را محاسبه نمی‌کند.
