# مهاجرت وب PromoGuard و تصمیم‌های طراحی

## تصمیم نهایی

PromoGuard از این نقطه دو رابط دارد:

1. `apps/dashboard` با Streamlit برای تحلیل سریع، توسعه الگوریتم و دموهای داخلی حفظ می‌شود.
2. `frontend` با Next.js و TypeScript رابط محصولی مدیر فروش است.
3. `apps/api` با FastAPI تنها مرز HTTP است و منطق اصلی همچنان در `src/promoguard` باقی می‌ماند.

این ساختار به ما اجازه می‌دهد UI را عوض کنیم بدون اینکه الگوریتم ممیزی، قرارداد داده و تست‌های آماری دوباره نوشته شوند.

## چرا Django فعلاً انتخاب نشد؟

Django برای محصولی که از ابتدا به احراز هویت، پنل ادمین، مدل‌های ORM و چند tenant نیاز دارد انتخاب خوبی است. اما PromoGuard در نقطه فعلی یک موتور تحلیل Python با API سبک است. FastAPI قراردادهای JSON و OpenAPI را ساده نگه می‌دارد و هزینهٔ مهاجرت از adapter فعلی کمتر است. اگر بعداً حساب کاربری، سازمان، صورتحساب و مدیریت دسترسی به هسته محصول تبدیل شوند، Django می‌تواند به‌عنوان سرویس حساب و back-office اضافه شود؛ آن تصمیم باید با نیاز واقعی مشتری گرفته شود، نه برای پیش‌بینی زودهنگام.

## مرز نسخه فعلی

این وب‌اپلیکیشن یک local demo محصولی است. تحلیل آن مشاهده‌ای است و به‌تنهایی اثر علّی، سود یا تضمین افزایش فروش را ثابت نمی‌کند. دادهٔ نمونه از فایل واقعی موجود در پروژه خوانده می‌شود و اعداد در فرانت hard-code نشده‌اند.

## اصول UX و رنگ

- مدیر باید در ۱۰ ثانیه بفهمد چه اتفاقی افتاده، چقدر مطمئنیم و قدم بعدی چیست.
- هر KPI یک عنوان فارسی روشن، واحد، مقدار و توضیح کوتاه دارد.
- آبی برای برند و اقدام اصلی، سبز برای وضعیت مثبت، کهربایی برای هشدار/نیاز به بررسی و قرمز فقط برای خطای جدی است.
- وضعیت فقط با رنگ منتقل نمی‌شود؛ متن، آیکن و برچسب نیز کنار آن هستند.
- پس‌زمینه خنثی و کارت‌های سفید سلسله‌مراتب را می‌سازند؛ رنگ برند روی همه صفحه پخش نشده است.
- نمودار، جدول متنی و توضیح ساده را هم‌زمان ارائه می‌کند تا عدد قابل بررسی باشد.

این تصمیم‌ها با راهنمای رسمی Fluent درباره palette، رنگ‌های معنایی، کنتراست و عدم اتکای تنها به رنگ هم‌خوان است.

## مسیر توسعه بعدی

### Gate 1 — تکمیل نسخه local web

- اجرای API و Next.js در دو process
- smoke test مرورگر
- تست endpoint ترکیبی داشبورد
- بررسی responsive و RTL

### Gate 2 — پایدار کردن قرارداد محصول

- شناسهٔ dataset و provenance به جای مسیر فایل محلی
- upload امن و job identifier
- گزارش ذخیره‌شده و قابل اشتراک
- تست contract بین frontend و API

### Gate 3 — پایلوت واقعی

- دریافت export مجاز از یک شرکت
- اجرای data readiness
- بازبینی نتیجه با مدیر فروش
- ثبت اینکه کدام insight به تصمیم واقعی کمک کرده است

تا Gate 3، نباید عبارت‌هایی مثل «سود قطعی» یا «اثر علّی پروموشن» در فروش استفاده شود.
