# برد اجرای تیم PromoGuard

آخرین به‌روزرسانی: ۲۵ شهریور ۱۴۰۵ / ۱۶ سپتامبر ۲۰۲۶

این برد برای موازی‌سازی کار تیم است. هر تسک باید یک owner، خروجی قابل بررسی، deadline و معیار
قبولی داشته باشد. «در حال انجام» بدون artifact یا PR وضعیت معتبر نیست.

## قوانین همکاری

1. هر عضو قبل از شروع، تسک را در گروه تأیید می‌کند.
2. هر تسک در یک branch جدا یا PR کوچک انجام می‌شود.
3. داده خصوصی شرکت‌ها وارد Git نمی‌شود.
4. داده fixture فقط برای تست است و business evidence محسوب نمی‌شود.
5. تغییر metric، estimator، threshold یا claim بدون review رضا وارد `main` نمی‌شود.
6. هر PR باید شامل توضیح، تست یا دلیل تست‌نشدن و limitation باشد.
7. اگر یک عضو منتظر داده یا تصمیم است، blocker را همان روز گزارش می‌کند؛ کار جایگزین انتخاب می‌شود.

## نقش‌ها و تسک‌های جاری

### رضا — Founder & Technical Lead

مسئولیت: معماری، مهندسی داده، مدل آماری/ML، API، تست، استقرار و release.

تسک‌های فوری:

- `T0`: تثبیت قرارداد Phase 8.1.1 و اصلاح ورودی‌های strict؛
- `T1`: تعریف API قرارداد feasibility بدون اتصال به داده خصوصی؛
- `T2`: نگهداری Demo Mode و جلوگیری از شکستن release عمومی؛
- `T3`: review و merge خروجی اعضا؛
- `T4`: ساخت quality report و ثبت تصمیم‌های روش‌شناسی.

خروجی هفته جاری: یک PR فنی سبز و یک تصمیم‌نامه درباره policy، uncertainty و unitهای اقتصادی.

### محمد مهدی اسماعیلیان — Product Discovery & Problem Lead

مسئولیت: مسئله، کاربر، KPI، مصاحبه و اولویت محصول.

تسک `P-01`:

- تعریف یک persona اصلی؛
- نوشتن ۱۰ سؤال مصاحبه؛
- انجام یا برنامه‌ریزی حداقل ۵ مصاحبه؛
- ثبت مشکل فعلی، ابزار فعلی و تصمیمی که مشتری می‌گیرد؛
- تعریف سه KPI که مشتری واقعاً برای آن‌ها تصمیم می‌گیرد؛
- نوشتن یک Problem Brief یک‌صفحه‌ای.

معیار قبولی: هر ادعا یک منبع یا یادداشت مصاحبه داشته باشد؛ عبارت‌های «بازار نیاز دارد» یا «مشتری
می‌خرد» بدون شاهد استفاده نشود.

### محمد شاهین‌فر — Data & Statistical Analysis Lead

مسئولیت: کیفیت داده، EDA، data dictionary و تحلیل آماری قابل بازتولید.

تسک `D-01`:

- ساخت data dictionary برای schema فعلی؛
- ثبت grain، کلیدها، نوع واحد و missingness؛
- نوشتن checklist کیفیت داده؛
- اجرای EDA روی داده عمومی موجود؛
- فهرست‌کردن سه خطر leakage و سه محدودیت inference؛
- پیشنهاد سه تحلیل با ورودی، خروجی و limitation مشخص.

معیار قبولی: خروجی با command قابل بازتولید باشد؛ هیچ ROI، profit یا causal lift بدون داده و روش
معتبر نوشته نشود.

### عضو چهارم — Business Development & Marketing Lead

مسئولیت: ارتباط صنعتی، توسعه کسب‌وکار، هماهنگی customer discovery و pilot.

تسک `B-01`:

- شناسایی ۱۰ مشتری یا واسطه بالقوه؛
- آماده‌سازی پیام معرفی؛
- تنظیم حداقل ۵ گفت‌وگو با رضایت طرف مقابل؛
- ثبت نوع صنعت، نقش مخاطب و مسئله مطرح‌شده؛
- تدوین طرح pilot کوچک؛
- ثبت وضعیت پیگیری بدون ادعای قرارداد یا مشتری.

معیار قبولی: هیچ نام شرکت یا فردی بدون اجازه وارد Git یا ارائه عمومی نشود؛ خروجی شامل وضعیت واقعی
ارتباط باشد: `identified`, `contacted`, `replied`, `interviewed`, `pilot_candidate`.

## مسیر موازی هفت‌روزه

```text
روز ۱: تقسیم تسک و تعیین owner
روز ۲-۳: مصاحبه/EDA/اصلاح قرارداد فنی
روز ۴: تحویل artifact اولیه و review رضا
روز ۵: اصلاح خروجی‌ها
روز ۶: جلسه تصمیم محصول و pilot
روز ۷: PRها، quality report و برنامه هفته بعد
```

## Definition of Done تیم

یک هفته فقط وقتی تمام‌شده است که:

- Problem Brief وجود داشته باشد؛
- Data Dictionary و quality checklist وجود داشته باشد؛
- حداقل یک مسیر واقعی ارتباط صنعتی ثبت شده باشد؛
- PR فنی تست‌شده باشد؛
- هیچ claim بدون evidence وارد اسناد نشده باشد؛
- تصمیم بعدی و blockerهای باقی‌مانده مشخص باشند.
