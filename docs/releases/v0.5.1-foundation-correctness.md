# PromoGuard v0.5.1 — Foundation correctness

This release repairs the analytical and public-contract foundation before any causal
benchmarking begins.

## Correctness changes

- renamed financial-looking output to an optional contribution sensitivity that cannot drive the
  recommendation;
- computes MASE scale only from consecutive non-promotion weeks;
- enforces canonical store/SKU identifiers at ingestion and application boundaries;
- confines filesystem API input to the local repository data root;
- reports paired forecast coverage and mutually exclusive exclusion reasons;
- carries a frozen, versioned AuditPolicy in every audit result.

## Ownership and repository changes

- added transparent AI/human responsibility boundaries and retrospective decision records;
- replaced the scaffold-oriented README with a reviewer-first current-state page;
- removed unused PostgreSQL, warehouse, and future-module placeholders;
- added Apache-2.0 for source code while keeping external dataset terms separate;
- aligned package and API versions at 0.5.1.

## Verified real-data evidence

- 67 tests pass; Ruff and compileall pass;
- 524,950 rows validate with no duplicate grain row or missing grain identifier;
- forecast comparison covers 41,516 paired rows (71.42% of eligible non-promotion test rows);
- the seasonal baseline does not beat recursive naive, and that negative result is preserved;
- representative audit remains observational and returns `needs_more_evidence`.

The machine-readable report is
`reports/foundation-correctness/release-quality-report.json`. Local gates and GitHub CI passed; the
release is marked by the annotated tag `v0.5.1-foundation-correctness`.
