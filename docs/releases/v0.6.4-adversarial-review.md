# PromoGuard v0.6.4 — adversarial review hardening

Release date: 2026-09-06

## Decision

This release closes the main Phase 6 engineering review. It is approved for local demonstration,
portfolio evidence, and reproducible benchmark discussion. It is not approved for autonomous
targeting, financial decisions, Iranian-market impact claims, or publication-holdout claims.

## Correctness repairs

- Refuse empty, non-finite, wrong-length, invalid-binary, and single-arm Qini inputs.
- Use zero Qini until both treatment arms appear in a ranked prefix.
- Retry and account for invalid tiny-sample Poisson bootstrap draws.
- Separate `qini_per_ranked_row` from the difference-in-means and IPW estimands.
- Rename the non-pristine `final_audit_holdout` to `post_freeze_audit_subset`.
- Add artifact schema version 1.1.0 and complete publisher provenance.
- Re-run all 13,979,592 real Criteo rows after the metric-contract change.

## Application hardening

- Reject missing and non-finite required unit values before retail analysis.
- Detect grain duplicates after identifier and date normalization.
- Reject column names that collide after whitespace normalization.
- Apply the byte-size limit to local API panel paths before loading.
- Return HTTP 422 when automatic audit selection finds no eligible event.
- Normalize numeric string inputs in forecasting and audit domain boundaries.
- Reject non-positive seasonal periods.
- Bound Streamlit data caches and disable audit execution for an invalid contribution input.

## Release integrity and security

- Replace duplicated package metadata with one version source; package, API, and wheel report 0.6.4.
- Add CLI integration tests and a headless Streamlit render test.
- Raise the combined coverage gate to 70%; the verified run is 72%.
- Add compile, dependency consistency, Bandit, pip-audit, and wheel-build gates to CI.
- Upgrade pytest and setuptools minimums after the security audit.
- Replace an optimization-removable runtime `assert` with an explicit error.

## CI runner postmortem

The first hardened CI attempt found `setuptools 79.0.1` in the GitHub runner even though the
project's isolated build environment required a safe newer version. Build-system requirements do
not upgrade the runner environment inspected by `pip-audit`. The workflow now upgrades both pip
and setuptools explicitly before installing and auditing the project. The following run passed all
quality, security, test, coverage, and wheel gates.
