# راهنمای اجرای پایلوت خصوصی PromoGuard

## راه‌اندازی از ریشهٔ پروژه

در PowerShell، داخل پوشهٔ پروژه:

```powershell
.venv/Scripts/python.exe -m pip install -e .
.venv/Scripts/python.exe -m uvicorn apps.api.main:app --host 127.0.0.1 --port 8000 --workers 1
```

در ترمینال دیگر داخل frontend:

```powershell
npm ci
npm run build
npm start -- --hostname 127.0.0.1 --port 3000
```

صفحه: http://127.0.0.1:3000/ . سلامت API: http://127.0.0.1:8000/health . نصب وابستگی‌ها باید در همان محیط پایتونی انجام شود که سرور را اجرا می‌کند؛ نصب در Python دیگری کافی نیست.

برای اجرای تست در همان محیط، وابستگی‌های توسعه را هم نصب کنید:

```powershell
.venv/Scripts/python.exe -m pip install -e '.[dev]'
.venv/Scripts/python.exe -m pytest -q
```

## فایل شرکت چه باشد؟

برای بارگذاری مستقیم وب، CSV استاندارد هفتگی با ستون‌های `week_end_date`, `store_id`, `upc`, `units`, `promotion_flag` لازم است. تاریخ به شکل YYYY-MM-DD و شناسه‌ها متن باشند. هر ردیف یک هفته، یک فروشگاه و یک کالا؛ promotion_flag فقط ۰ یا ۱. ردیف گمشده را بدون تأیید معنای آن صفر نکنید.

خروجی شرکت ممکن است `date` و `sku_id` یا نام‌های دیگری داشته باشد؛ ابتدا طبق قرارداد مشتری و مسیر intake به پنل استاندارد تبدیل می‌شود. آپلود مستقیم، نگاشت دلخواه ستون و تبدیل خودکار فایل روزانه به هفتگی را پشتیبانی نمی‌کند. این تفاوت باید در تماس با شرکت شفاف گفته شود.

درخواست اولیه: فروش کالاها و هم‌دسته‌ها، تاریخ و مشخصات کمپین، نوع تخفیف و وضعیت اجرای آن؛ ترجیحاً یک سال تاریخچه برای انتخاب رویداد نماینده و حداقل چهار هفتهٔ کامل بعد کمپین. کمبود تاریخچه ممکن است انتخاب یا کیفیت تحلیل را محدود کند. هزینهٔ واحد، درآمد، قیمت و موجودی اگر در دسترس باشند جداگانه با تعریف دقیق واحد پول و زمان ثبت دریافت شوند. نبود این‌ها باید محدودیت گزارش بماند.

نام، تلفن، کد ملی و اطلاعات فردی مشتریان را نخواهید. از صاحب داده اجازهٔ استفاده، محدودهٔ تحلیل، افراد مجاز به دیدن گزارش و زمان حذف را مکتوب بگیرید. این نسخه به‌تنهایی قرارداد حقوقی یا تضمین محرمانگی نیست.

## مسیر کار

بارگذاری → کنترل کیفیت → انتخاب رویداد → ساخت گزارش → مشاهدهٔ پیشرفت → بررسی جزئیات → PDF. در منوی گزارش‌های ذخیره‌شده، سابقه را باز کنید. اگر کار با خاموش‌شدن سرویس قطع شد، تلاش مجدد یک شناسهٔ جدید می‌سازد. در خطای تغییر اثر انگشت فایل، منبع را بررسی و نسخهٔ صحیح را دوباره بارگذاری کنید؛ کنترل صحت را دور نزنید.

## ذخیره و پشتیبان

اطلاعات در `tmp/product-runtime/pilot.sqlite` و فایل‌ها در زیرپوشه‌های datasets و reports هستند. حذف این پوشه به معنی حذف داده و سابقه است. آن را با پوشهٔ موقت قابل دورریختن اشتباه نگیرید. در این نسخه پاک‌سازی خودکار اجرا نمی‌شود.

برای پشتیبان ساده، هر دو سرور را متوقف کنید و کل پوشهٔ product-runtime را در محل خصوصی با دسترسی محدود کپی کنید؛ فایل SQLite فعال را جدا از فایل‌های WAL کپی نکنید. بازیابی باید شامل دیتابیس، فایل‌های داده و گزارش‌ها در مسیر اولیه باشد. نسخه‌های پشتیبان هم مشمول توافق حذف هستند.

## محدودیت انتشار

فقط یک worker و یک نمونهٔ سرور. startup کارهای ناتمام را ناموفق می‌کند؛ اجرای چند نمونهٔ همزمان این منطق را نقض می‌کند. بدون login و tenant isolation، تمام مراجعه‌کنندگان مجاز به این سرویس محلی می‌توانند گزارش‌ها را بخوانند. روی 0.0.0.0، تونل عمومی یا هاست عمومی منتشر نکنید. «پوشهٔ خصوصی» به معنی امنیت سازمانی پیاده‌شده نیست.

## پذیرش پایلوت

پذیرش فنی: فایل معتبر، انتخاب کمپین درست، اعداد قابل بازسازی، PDF دارای شناسه، سابقه پس از restart و خطاهای قابل پیگیری. پذیرش تجاری: مدیر فروش بگوید کدام یافته به تصمیم واقعی کمک کرده؛ این بخش هنوز نیازمند شرکت و مصاحبه است. بعد از آن دربارهٔ کاربران، سازمان‌ها و خدمات پولی تصمیم بگیرید.
