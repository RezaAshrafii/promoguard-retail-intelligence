## ب — اطلاعات ایده

### عنوان ایده

PromoGuard: سامانه قابل ممیزی ارزیابی پروموشن و تصمیم‌یار فروش خرده‌فروشی

### شرح ایده

PromoGuard یک سامانه تحلیل داده است که داده فروش هفتگی فروشگاه‌ها و اطلاعات پروموشن را دریافت و
ابتدا کیفیت آن را کنترل می‌کند. سپس دوره‌های پروموشن را شناسایی و فروش مشاهده‌شده را با baseline
ساخته‌شده فقط از تاریخچه پیش از رویداد مقایسه می‌کند. خروجی شامل بازه عدم‌قطعیت، هشدار کمبود
داده، ریسک خرید پیش‌دستانه، نبود داده موجودی یا هزینه، و توصیه اولیه برای اولویت‌دادن به آزمون
کنترل‌شده، جمع‌آوری شواهد بیشتر یا کم‌اولویت‌سازی و بررسی علت است. محصول ادعای تشخیص قطعی اثر علّی یا سود قطعی ندارد و برای
تصمیم‌گیری مرحله اول و طراحی آزمون قابل دفاع ساخته شده است.

### کارهای مطالعاتی انجام‌شده

**پیشنهاد علامت فرم: بله.**

مطالعه و پیاده‌سازی بر پایه یک دیتاست عمومی خرده‌فروشی انجام شده است. قرارداد داده، کنترل کیفیت،
پنل هفتگی، baseline زمانی، ممیزی observational پروموشن، API تایپ‌شده، داشبورد فارسی و تست‌های
خودکار توسعه یافته‌اند. روی داده عمومی واقعی ۵۲۴٬۹۵۰ ردیف پردازش و مسیر end-to-end بازتولید شده
است. مستندات و artifactهای قابل بررسی در repository قرار دارند.

### اجزا، ملزومات و نحوه عملکرد

**پیشنهاد علامت فرم: بله.**

اجزا شامل loader داده، کنترل کیفیت، پنل فروش هفتگی، موتور baseline، موتور ممیزی پروموشن،
FastAPI، داشبورد Streamlit و گزارش JSON است. ورودی MVP فایل CSV استاندارد یا پنل محلی است؛
برای اجرای واقعی در شرکت، اتصال به داده فروش، تقویم پروموشن و در صورت دسترسی margin و موجودی
نیاز است. محاسبات در هسته Python انجام می‌شوند و API/داشبورد فقط لایه ارائه‌اند.

### مطالعات آزمایشگاهی و دوره‌های آموزشی

**پیشنهاد علامت فرم: فقط مطابق واقعیت انتخاب شود.**

متن امن: «مطالعات فنی و پیاده‌سازی نرم‌افزاری انجام شده است. دوره یا گواهی رسمی فقط در صورت داشتن
مدرک واقعی در این بخش درج می‌شود.»

### آیا MVP ساخته شده است؟

**پیشنهاد علامت فرم: بله.**

نسخه `v0.4.0-phase-04` شامل API، داشبورد فارسی، گزارش کیفیت، شناسایی دوره پروموشن، گزارش ممیزی
و مسیر دموی واقعی است. ۴۷ تست خودکار و اجرای عملی روی داده عمومی مستند شده‌اند. MVP هنوز به
داده یک مشتری ایرانی متصل نشده و اثر اقتصادی آن در محیط کسب‌وکار اندازه‌گیری نشده است.

### نمونه اولیه و رفع ایراد

**پیشنهاد علامت فرم: بله، با توضیح مرحله‌ای بودن.**

در بازبینی رابط، هشدارهای serialization و API منسوخ Streamlit شناسایی و اصلاح شد؛ سپس مسیر کامل
بارگذاری تا تحلیل دوباره اجرا و بدون warning/error سرور ثبت شد. بهبودهای production مانند
authentication، database cache و monitoring هنوز در roadmap هستند.

### بررسی تولید انبوه یا نیمه‌صنعتی

**پیشنهاد علامت فرم: خیر / در مرحله مطالعه.**

این ایده نرم‌افزاری است. معادل مقیاس‌پذیری آن، اجرای pilot داده‌ای و سپس طراحی زیرساخت production
است. هنوز بهره‌برداری نیمه‌صنعتی یا مشتری production ادعا نمی‌شود.

### برآورد مالی

**پیشنهاد علامت فرم: خیر / نیازمند pilot.**

هزینه و مدل درآمدی بدون مصاحبه با مشتری و تعریف دامنه pilot اعتبار ندارد. در pilot ۹۰ روزه، زمان
دریافت داده، پاکسازی، هزینه زیرساخت و willingness-to-pay با شریک واقعی اندازه‌گیری می‌شود.
