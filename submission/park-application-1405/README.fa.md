# بسته ارائه ایده — PromoGuard Retail Intelligence

این پوشه برای ارائه تا ۱۳ شهریور ۱۴۰۵ آماده شده است. هر فایل یک وظیفه روشن دارد و هیچ‌کدام نباید
بدون شخصی‌سازی اطلاعات فردی، نام دانشگاه، تاریخ و لینک‌های نهایی ارسال شود.

## ترتیب استفاده

1. ابتدا `MASTER-SUBMISSION-ROADMAP-FA.md` را بخوان؛ ترتیب gateها و معیار ارسال در آن ثبت شده است.
2. `form-response-fa.md` را با اطلاعات شخصی واقعی کامل کن و پاسخ‌ها را در فرم رسمی وارد کن.
3. `one-page-brief-fa.md` را به‌عنوان خلاصه‌ای که داور سریع می‌خواند، ضمیمه یا در سامانه کپی کن.
4. `architecture-and-90day-plan-fa.md` را فقط وقتی بفرست که جزئیات فنی یا برنامه اجرای آزمایشی
   می‌خواهند.
5. `risk-register-fa.md` پاسخ آماده برای پرسش‌های ریسک و بلوغ طرح است.
6. برای ضبط، `video-production-plan-fa.md` مرجع اصلی و `demo-script-2min-fa.md` متن اولیه است.
7. `evidence-index.md` نقشه اتصال هر ادعا به کد، تست یا artifact واقعی است.

## قانون ارائه

- «نمونه اولیه قابل اجرا» ادعا می‌شود، چون کد، API، داشبورد و اجرای داده واقعی وجود دارد.
- «اثبات اثر اقتصادی» ادعا نمی‌شود، چون هنوز customer pilot، cost واقعی و طراحی آزمایش کنترل‌شده
  نداریم.
- «بازار هدف» و «درخواست pilot» فرضیه و برنامه اعتبارسنجی هستند، نه مشتری یا قرارداد فعلی.
- هر جای‌خالی داخل `<...>` باید پیش از ارسال با واقعیت تکمیل شود.

## وضعیت نسخه و اعداد

آخرین tag کامل پیش از gate فعال `v0.5.0-phase-05` است. Release Gate 5.1 هنوز فعال است؛ بنابراین
نسخه نهایی، تعداد تست و اعداد بسته فقط پس از تولید quality report نهایی freeze می‌شوند. عددهای
قدیمی نباید با حدس یا جایگزینی دستی به‌روزرسانی شوند. اجرای evidence path با
`python -m demo.phase4_smoke` انجام می‌شود و گزارش فعلی آن در `reports/phase-04/demo-smoke.json`
قرار دارد.
