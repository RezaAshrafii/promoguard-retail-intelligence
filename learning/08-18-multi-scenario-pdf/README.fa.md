# راهنمای فاز ۸٫۲٫۹: اطمینان از گزارش چندسناریویی

## چرا این مرحله لازم بود؟

نسخهٔ قبل گزارش PDF را با یک سناریو آزمایش می‌کرد. اما کاربر ممکن است چند کالا یا فروشگاه را برای بررسی وارد کند. گزارش باید در چند صفحه ادامه پیدا کند و شناسه‌ها و منبع‌های هر گزینه را با هم قاطی نکند.

## چه چیزی اضافه شد؟

یک تست API ساخته شد که هشت سناریوی مستقل را به مسیر PDF می‌فرستد. هر سناریو شناسهٔ فروشگاه، کالا و مرجع منبع جدا دارد. تست بررسی می‌کند که:

1. درخواست موفق باشد و واقعاً PDF برگردد.
2. PDF بیشتر از دو صفحه داشته باشد؛ یعنی مسیر چندصفحه‌ای اجرا شده باشد.
3. شناسهٔ هر هشت سناریو در متن استخراج‌شدهٔ PDF دیده شود.
4. مرجع دادهٔ تقاضا برای هر سناریو در گزارش باقی بماند.

## این تست چه چیزی را ثابت نمی‌کند؟

ورودی‌ها ساختگی و فقط برای آزمایش نرم‌افزارند. این تست صحت سود، کیفیت پیش‌بینی تقاضا، معتبر بودن منابع، یا مفید بودن تصمیم برای مدیر فروش را ثابت نمی‌کند. برای آن‌ها به دادهٔ مجاز شرکت و بازبینی مدیر نیاز داریم.

## چطور اجرا شود؟

از ریشهٔ پروژه:

```powershell
python -m pytest -q tests/integration/test_api.py -k "manager_scenario_pdf"
```

اگر تست پاس شد، فقط می‌دانیم PDF چندسناریویی ساخته می‌شود و اطلاعات پایهٔ سناریوها در متن خروجی باقی می‌ماند. چیدمان بصری باید جداگانه با رندر صفحات و بازبینی انسانی کنترل شود.
