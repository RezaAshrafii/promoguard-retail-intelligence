# گام ۸.۲.۸ — خروجی PDF برای بازبینی سناریوی مدیر

تاریخ: ۱۴ اکتبر ۲۰۲۶<br>
مدل: مدل جاری Codex برای پیاده‌سازی adapter؛ در این نشست انتخاب مدل یا سطح reasoning جداگانه در اختیار نبود. روش مالی یا آماری جدیدی طراحی نشده و بازبینی مستقل دوم ادعا نمی‌شود.

## مسئله‌ای که حل شد

صفحهٔ بررسی سناریوها، نتیجه را فقط داخل مرورگر نشان می‌داد. مدیر برای مرور کنار همِ ورودی‌های ثبت‌شده و نتیجه، فایل قابل ارسال نداشت. حالا بعد از نمایش نتیجه، دکمه‌ای برای دانلود PDF وجود دارد.

## مسیر اجرا

۱. صفحهٔ `/optimization` همان JSON را برای API مقایسه می‌فرستد.<br>
۲. پس از پاسخ موفق، متن دقیق همان درخواست در حافظهٔ همان صفحه نگه داشته می‌شود.<br>
۳. دکمهٔ PDF همین ورودی را به مسیر `POST /v1/optimization/comparisons/pdf` می‌فرستد.<br>
۴. API با همان قراردادها، محاسبهٔ قطعی را دوباره انجام می‌دهد و PDF را از ورودی و پاسخ تایپ‌شده می‌سازد.<br>
۵. فایل دانلود می‌شود؛ پاسخ `Cache-Control: no-store, private` دارد و متن درخواست و گزارش روی سرور ذخیره نمی‌شوند.

دوباره‌محاسبه‌کردن عمداً از ارسال نتیجهٔ دستکاری‌پذیر مرورگر جلوگیری می‌کند. محاسبه فقط در `src/promoguard/optimization` است؛ PDF و صفحه نقش نمایش و انتقال دارند.

## چه چیزی در PDF می‌آید؟

- شناسهٔ درخواستی که کاربر داده، آستانهٔ مدیر و مرجع و نام ثبت‌شده؛
- جمع‌بندی حد پایین، مقدار میانی و حد بالای سود افزودهٔ شرطی برای هر سناریو؛
- سود مبنا و کمپین، سهم هر واحد، هزینهٔ معاملاتی، موجودی قابل فروش و توضیح وضعیت؛
- برای هر ورودی اقتصادی، نوع منبع، مرجع، تاریخ و نام تأییدکنندهٔ ثبت‌شده؛
- محدودیت‌ها و یک چک‌لیست کوتاه برای تطبیق ارقام با مدارک اصلی.

مقادیر مالی در قالب `Decimal` خروجی گرفته می‌شوند و هنگام ساخت PDF به `float` تبدیل نمی‌شوند. متن‌های کاربر پیش از رندر HTML-escape می‌شوند. نام و مرجع‌ها فقط چیزی هستند که در ورودی نوشته شده‌اند؛ سامانه هویت یا اصالت سند را بررسی نمی‌کند.

## مرزهای مهم

- PDF، Report ID تازه یا لینک اشتراک‌گذاری پایدار تولید نمی‌کند؛ شناسهٔ داخل آن همان `request_id` ورودی است.
- هیچ ورودی یا خروجی سناریویی در سرور ذخیره نمی‌شود؛ این نسخه سامانهٔ احراز هویت یا کنترل دسترسی سازمانی نیست.
- «بازهٔ تقاضا» ورودی سناریویی است، نه فاصلهٔ اطمینان و نه اثر علّی.
- سناریوها رتبه‌بندی یا انتخاب نمی‌شوند، بودجه بین آن‌ها تقسیم نمی‌شود و کمپینی اجرا نمی‌شود.
- fixtureهای تست فقط برای آزمون قرارداد نرم‌افزارند؛ نتیجه یا دادهٔ مشتری محسوب نمی‌شوند.

## فایل‌های تغییرکرده

- `apps/api/pdf.py`: قالب فارسی برای خلاصه، تفصیل هر سناریو، ردیابی ورودی‌ها و محدودیت‌ها.
- `apps/api/main.py`: مسیر دانلود PDF؛ پاسخ مستقیم و بدون ذخیره‌سازی سمت سرور.
- `frontend/app/optimization/page.tsx`: دکمهٔ دانلود، خطای قابل فهم، قفل و وضعیت آماده‌سازی؛ درخواست منبع نتیجه حفظ می‌شود.
- `frontend/app/optimization/optimization.module.css`: چیدمان کنش‌های دانلود و پیام خطا.
- `frontend/e2e/optimization-report.spec.ts`: آزمون مرورگر با API ساختگی و بررسی اینکه بدنهٔ PDF همان درخواست سازندهٔ نتیجه است.
- `tests/integration/test_api.py`: آزمون مسیر API واقعی، PDF معتبر، metadata، منابع، متن ورودی مخرب، واحد پول و مقدار مالی.
- `ROADMAP.md`, `README.md`, `docs/limitations.md`: ثبت توانایی تازه و محدودیت ذخیره‌سازی.

## آزمون‌ها و شاهد

- `python -m ruff check apps/api/pdf.py apps/api/main.py tests/integration/test_api.py` — پاس.
- `python -m pytest -q tests/integration/test_api.py -k 'manager_scenario'` — ۳ تست پاس.
- `python -m pytest -q` — کل مجموعهٔ پایتون: ۲۹۹ تست پاس؛ یک هشدار deprecation از Starlette/httpx.
- `python -m compileall -q apps/api` — پاس.
- در پوشهٔ `frontend`: `npm run lint`, `npm test` (۱۳ تست)، `npm run typecheck`, `npm run build` — پاس.
- `npx playwright test --workers=1` — ۸ تست مرورگر پاس؛ شامل دانلود PDF و حفظ دقیق متن درخواست.
- از یک درخواست fixture تستی، API فایل PDF به اندازهٔ ۳۷٬۸۹۹ بایت و دو صفحه ساخت. هر دو صفحه با رندر محلی از نظر نبود بریدگی/سرریز بررسی شدند. صفحهٔ دوم محدودیت‌ها و چک‌لیست مدیر را دارد.
- یک هشدار upstream مربوط به استفادهٔ `httpx` با `starlette.testclient` در تست API باقی است.

## جمع‌بندی خیلی ساده

مثل این است که صفحه نتیجهٔ یک برگهٔ محاسبه را نشان دهد و حالا همان ورودی را دوباره به ماشین حساب اصلی بدهد تا نسخهٔ قابل چاپ بسازد. مرورگر عدد تازه‌ای حساب نمی‌کند و PDF هم نمی‌گوید «این کمپین را اجرا کن»؛ فقط اعداد و منبع‌هایی را که وارد شده‌اند مرتب می‌کند تا مدیر بتواند آن‌ها را بررسی کند.

## پرسش تمرینی

**چرا PDF را از پاسخ مرورگر نمی‌سازیم؟**<br>
چون پاسخ مرورگر را می‌شود تغییر داد. API باید با ورودی ثبت‌شده دوباره محاسبه کند تا فایل قابل دانلود از همان قرارداد و منطق معتبر سرور ساخته شود.

**آیا این PDF به معنی گزارش ذخیره‌شده یا مشتری واقعی است؟**<br>
نه. فایل مستقیم دانلود می‌شود و سرور آن را نگه نمی‌دارد. آزمون فعلی فقط رفتار فنی را با ورودی fixture می‌سنجد.

**چه زمانی می‌توان آن را گزارش سود واقعی نامید؟**<br>
وقتی دادهٔ مجاز شرکت، تعریف تأییدشدهٔ هزینه و حاشیهٔ سود، روش قابل دفاع برآورد تقاضا و بازبینی مدیر مسئول وجود داشته باشد. حتی آن زمان، ادعا باید متناسب با روش و محدودیت‌ها بماند.
