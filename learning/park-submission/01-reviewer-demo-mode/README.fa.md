# Demo Mode مخصوص داور — راهنمای کامل و ساده

## هدف کلی

داور نباید برای فهم محصول مسیر فایل وارد کند، بین ۴۹ هزار رویداد بگردد یا JSON بخواند. Demo Mode
یک مسیر یک‌کلیکی روی همان داده واقعی می‌سازد: ابتدا کیفیت را کنترل می‌کند، سپس رویداد نماینده را با
قانون ثابت برمی‌گزیند و در پایان نتیجه، بازه عدم‌قطعیت و هشدار را نشان می‌دهد.

این بخش مدل آماری جدید نساخت. وظیفه‌اش این بود که نتیجه درست هسته را بدون تحریف، قابل دیدن کند.

## معماری به زبان ساده

```text
دکمه دمو
  -> load_weekly_panel (داده واقعی محلی)
  -> validate_canonical_panel (اجازه ادامه یا توقف)
  -> select_representative_event (انتخاب قانون‌مند، نه دست‌چین)
  -> audit_promotion_event (تمام محاسبات در domain)
  -> PromotionAuditResult (منبع واحد عددها)
  -> presentation.py (فقط ترجمه و چیدمان)
  -> Streamlit (نمایش)
```

اگر داده خراب باشد، زنجیره در validation متوقف می‌شود. اگر فایل محلی وجود نداشته باشد، کاربر فقط
یک پیام عمومی و دستور relative برای ingest می‌بیند؛ مسیر شخصی ویندوز یا stack trace نشان داده
نمی‌شود.

## سه مرحله‌ای که داور می‌بیند

### مرحله ۱ — داده و کیفیت

با کلیک روی دکمه، پنل ۵۲۴٬۹۵۰ ردیفی خوانده می‌شود. تعداد سری‌ها، ردیف‌های پروموشن، تکرار grain و
بازه زمانی نمایش داده می‌شوند. صفر بودن duplicate به این معنی است که برای یک هفته، فروشگاه و کالا
دو رکورد رقیب نداریم.

### مرحله ۲ — رویداد بدون cherry-pick

کد نخستین رویدادی را پیدا می‌کند که طبق policy نسخه 1.0.0 حداقل ۵۲ هفته تاریخچه و پنجره بعد از
رویداد کامل داشته باشد. بنابراین ما بعد از دیدن نتیجه، نمونه زیبا انتخاب نکرده‌ایم. رویداد فعلی:

- فروشگاه 23345؛
- UPC برابر 2840004768؛
- شروع 2010-01-13؛
- مدت ۵ هفته.

### مرحله ۳ — نتیجه و محدودیت

فروش مشاهده‌شده ۱۲۸ واحد است. baseline نقطه‌ای ۱۸۵ و بازه آن [۱۱۵، ۲۵۵] است. اختلاف مشاهده‌شده
با baseline برابر -۵۷ و بازه اختلاف [-۱۲۷، ۱۳] است. چون بازه اختلاف صفر را قطع می‌کند و هشدار
forward-buy مسدودکننده وجود دارد، سیستم می‌گوید `needs_more_evidence`.

این یعنی «فعلاً نمی‌دانیم»، نه اینکه پروموشن حتماً بد بوده است. موجودی، هزینه و counterfactual
واقعی نداریم؛ پس سود و اثر علّی ادعا نمی‌شود.

## چرا فایل presentation جدا شد؟

`apps/dashboard/presentation.py` فقط چهار کار می‌کند: انتخاب متن فارسی ثابت، کپی مقدار observed و
baseline برای نمودار، ساخت خلاصه identity رویداد و ترجمه کد هشدار. این فایل جمع، تفریق، forecast
یا تصمیم‌گیری ندارد. به همین علت می‌توانیم UI را زیباتر کنیم بدون اینکه عدد علمی تغییر کند.

## فایل‌های تغییرکرده

- `apps/dashboard/app.py`: حالت `--demo`، سه مرحله، CSS فارسی، نمودار interval و failure-safe.
- `apps/dashboard/presentation.py`: mappingهای pure و قابل تست.
- `tests/unit/test_dashboard_presentation.py`: شش تست mapping و مرز ادعا.
- `docs/api-dashboard.md`: دستور اجرا و contract دموی داور.
- `reports/phase-05/demo-mode-quality-report.json`: شاهد ماشین‌خوان اجرای واقعی و مرورگر.
- `submission/.../screenshots/03...png` و `04...png`: تصاویر واقعی نهایی.
- `video-production-plan-fa.md`: checklist پیاده‌سازی و متن دقیق دکمه.

## تست و بازبینی انجام‌شده

شش تست presentation پاس شد. سپس Streamlit واقعی با `--demo` اجرا و دکمه در مرورگر کلیک شد. نتیجه
روی پنل کامل ظاهر شد، نمودار observed/baseline/interval دیده شد و جست‌وجوی متن صفحه نشان داد مسیر
شخصی و Traceback وجود ندارد. دو screenshot جدید از event/result و chart/warnings ذخیره شد.

## دستور اجرا برای ضبط

```powershell
Set-Location "<repository-root>"
.\.venv\Scripts\Activate.ps1
streamlit run apps/dashboard/app.py -- --demo
```

قبل از برداشت نهایی یک بار دمو را اجرا کنید تا cache گرم شود. سپس صفحه را refresh و دوباره دکمه
را بزنید. کوتاه‌کردن زمان loading در تدوین مجاز است، ولی نباید وانمود کنید loading وجود ندارد.

## سؤال‌های محتمل مصاحبه

**چرا React نساختید؟** چون ریسک اصلی صحت و اعتماد بود. Streamlit موجود تمام evidence لازم را با
هزینه کمتر ارائه می‌دهد؛ React در این deadline ارزش تحلیلی اضافه نمی‌کرد.

**آیا نمودار خودش محاسبه می‌کند؟** خیر. فقط `observed_units` و سه مقدار interval از typed result را
نقاشی می‌کند.

**چرا نتیجه منفی را نشان می‌دهید؟** چون سیستم باید توانایی abstain داشته باشد. نمایش فقط نمونه موفق
داور را درباره cherry-pick و اعتبار علمی بدبین می‌کند.

**آیا داده مصنوعی است؟** خیر. اجرای ارائه روی داده عمومی واقعی dunnhumby است و raw data به دلیل
مجوز و حجم در Git قرار نگرفته است.

## محدودیت باقی‌مانده

این یک local demo است، نه سرویس اینترنتی production. برای deployment عمومی باید upload امن،
authentication، storage کنترل‌شده، rate limit و monitoring ساخته شود. این‌ها فعلاً قابلیت موجود
معرفی نمی‌شوند.
