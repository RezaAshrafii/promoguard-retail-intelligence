# تازه‌سازی شواهد پرونده پارک — راهنمای کامل

## چرا این بخش لازم بود؟

بعد از هر release، متن فرم ممکن است از کد عقب بماند. در پرونده قبلی هنوز نسخه 0.4.0 و ۴۷ تست نوشته
شده بود، در حالی که نسخه واقعی 0.5.2 و تعداد تست تأییدشده ۷۳ بود. تغییر دستیِ پراکنده خطرناک است؛
ممکن است یک فایل ۷۳ و فایل دیگر ۴۷ بگوید و داور اعتمادش را از دست بدهد.

برای همین `submission-quality-report.json` به منبع حقیقت پرونده تبدیل شد. هر عدد بیرونی باید یا از
این فایل بیاید یا به‌وضوح فرضیه باشد.

## چه چیزهایی freeze شدند؟

- release ارائه: `v0.5.2-park-demo`؛
- release correctness: `v0.5.1-foundation-correctness`؛
- تست: ۷۳ پاس؛
- ردیف داده: ۵۲۴٬۹۵۰؛
- سری فروشگاه–کالا: ۳٬۹۰۹؛
- ردیف پروموشن: ۱۴۹٬۳۸۶؛
- audit: فروش ۱۲۸، baseline برابر ۱۸۵، اختلاف -۵۷؛
- توصیه: `needs_more_evidence`؛
- warning مسدودکننده: `FORWARD_BUY_RISK`.

## چه فایل‌هایی هماهنگ شدند؟

- `form-response-fa.md`: نسخه، تعداد تست، Demo Mode و warning باقی‌مانده صادقانه اصلاح شد.
- `one-page-brief-fa.md`: شاهد ۷۳ تست و Demo Mode اضافه شد.
- `README.fa.md`: tagها و دو quality report منبع حقیقت شدند.
- `MASTER-SUBMISSION-ROADMAP-FA.md`: کارهای واقعاً تمام‌شده تیک خوردند.
- `evidence-index.md`: هر ادعای جدید به report، code یا test وصل شد.
- `submission-quality-report.json`: همه واقعیت‌های freeze‌شده و کارهای بیرونی باقی‌مانده را یکجا دارد.

## چرا placeholderهای شخصی حذف نشدند؟

چون نام کامل قانونی، تاریخ تولد، دانشگاه، کد ملی، نشانی، تلفن و امضا را نباید حدس زد یا داخل Git
گذاشت. placeholderهای داخل فرم پیش‌نویس «خطای پروژه» نیستند؛ علامت توقف ایمنی هستند. قبل از ارسال،
رضا آن‌ها را در نسخه خصوصی فرم جایگزین می‌کند. فایل عمومی Git همچنان بدون داده هویتی حساس می‌ماند.

## مرز تصمیم شما

اکنون بخش فنی و عددی قابل دفاع است، ولی پرونده هنوز خودکار آماده ارسال نیست. شما باید این موارد را
شخصاً تصمیم و تکمیل کنید:

1. نام و اطلاعات هویتی واقعی؛
2. دانشگاه و گواهی اشتغال به تحصیل؛
3. نتیجه تماس یا مکاتبه برای شرایط احراز؛
4. فایل ویدیوی نهایی و لینک بدون login؛
5. امضا و ارسال نهایی؛
6. هر ادعای مصاحبه، مشتری یا pilot فقط با مدرک واقعی.

## سؤال مصاحبه‌ای

**چطور consistency بسته را تضمین کردی؟**

«یک JSON ماشین‌خوان را منبع حقیقت کردم، نسخه و تست را فقط از release/CI خواندم، همه متن‌های بیرونی
را با جست‌وجوی stale reference ممیزی کردم و placeholderهای هویتی را به‌جای حدس‌زدن عمداً نگه
داشتم. سپس claim audit بررسی کرد هر ادعا evidence یا برچسب فرضیه داشته باشد.»

## claim audit نهایی چه چیزی را کنترل کرد؟

بازبینی نهایی با مدل `gpt-5.6-sol` و reasoning سطح `xhigh` انجام شد، چون این مرحله درباره زیبایی متن
نبود؛ درباره جلوگیری از ادعای بیش از شواهد بود. نتیجه در
`reports/phase-05/submission-claim-audit.json` ثبت شد:

- هیچ نسخه یا تعداد تست قدیمی در پوشه ارسال باقی نماند؛
- هر ۷ placeholder فقط مربوط به اطلاعات خصوصی و واقعی متقاضی است؛
- MVP محلی، اجرای داده واقعی و Demo Mode ادعاهای پشتیبانی‌شده‌اند؛
- اثر علّی، سود، مشتری ایرانی، قرارداد، درآمد و production readiness ادعا نشده‌اند؛
- بازار هدف «فرضیه» و برنامه ۹۰روزه «برنامه آینده» باقی مانده‌اند؛
- repository، release و README با درخواست بدون authentication پاسخ HTTP 200 دادند؛
- مخزن عمومی است و License آن Apache-2.0 تشخیص داده شد.

این یعنی **بسته شواهد عمومی آماده است**، اما **ارسال رسمی هنوز آماده نیست**. تفاوت این دو مهم است:
کد و ادعاهای عمومی مشکلی ندارند، ولی فرم امضاشده، اطلاعات هویتی، مدارک دانشگاهی، احراز شرایط و لینک
ویدیوی نهایی فقط باید توسط رضا و خارج از Git تکمیل شوند.
