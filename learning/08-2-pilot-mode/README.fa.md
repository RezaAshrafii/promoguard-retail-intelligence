# راهنمای ساده: حالت پایلوت PromoGuard

این مرحله مسیر «فایل فروش را می‌دهم، گزارش همان کمپین را می‌گیرم» را به محصول وصل می‌کند. هدف
هنوز اثبات اثر علّی یا سود نیست؛ هدف این است که جریان کار از ابتدا تا خروجی قابل پیگیری باشد.

## مسیر کاربر

1. کاربر یک CSV فروش هفتگی بارگذاری می‌کند.
2. سرور فایل را می‌خواند، ساختار canonical را کنترل می‌کند و برای محتوای فایل شناسهٔ پایدار
   `dataset_id` می‌سازد. فایل‌های بیش از حد مجاز یا CSV خراب رد می‌شوند.
3. فهرست پروموشن‌های تشخیص‌داده‌شده از همان فایل نمایش داده می‌شود. کاربر فروشگاه، کالا و تاریخ
   شروع موردنظرش را انتخاب می‌کند.
4. با درخواست گزارش، شناسه‌ای مثل `rpt_...` ساخته می‌شود. درخواست به کار پس‌زمینه می‌رود و فرانت
   وضعیت را می‌پرسد تا آماده‌شدن یا خطا را نشان دهد.
5. گزارش نتیجهٔ همان رویداد انتخابی را نگه می‌دارد: فروش مشاهده‌شده، خط مبنای برآوردی، بازه‌های
   قبل/حین/بعد، هشدارها، جدول هم‌دسته‌ها و تصمیم بعدی.
6. دکمهٔ دریافت PDF از شناسهٔ گزارش واقعی استفاده می‌کند. PDF فارسی با Vazirmatn ساخته می‌شود و
   شناسه، خلاصه، بازه‌ها، پیشنهاد بعدی و مرزهای ادعا را دارد.

## تغییر فنی این برش

- `GET /v1/datasets/{dataset_id}/promotions` رویدادهای قابل انتخاب فایل را برمی‌گرداند.
- `POST /v1/reports` علاوه بر شناسهٔ داده، می‌پذیرد `store_id`, `upc`, `start_date` را با هم
  دریافت کند؛ اگر فقط بخشی از کلید ارسال شود، درخواست رد می‌شود.
- گزارش پس‌زمینه دقیقاً همان رویداد را ممیزی می‌کند و `selected_event` را در وضعیت گزارش نگه
  می‌دارد.
- فرانت پس از بارگذاری، به‌جای انتخاب پنهانی کمپین، فهرست رویدادها را نشان می‌دهد.
- PDF از همان payload گزارش ساخته می‌شود، نه از یک نمونهٔ ثابت.

## چطور تست شد؟

تست چرخهٔ محصول CSV را بارگذاری می‌کند، رویداد را از API می‌گیرد، همان رویداد را به گزارش
می‌فرستد، وضعیت نهایی را می‌خواند و PDF را باز می‌کند. آزمون PDF تعداد صفحه، عنوان، شناسهٔ
گزارش و فرمت فایل را کنترل می‌کند. فرانت هم با `npm run typecheck` و `npm run build` بررسی
می‌شود.

## محدودیت‌هایی که باید صادقانه بگوییم

- این استقرار برای پایلوت کنترل‌شده است، نه سرویس عمومی آمادهٔ چندسازمانی.
- فهرست dataset و report در حافظهٔ پردازش نگهداری می‌شود؛ فایل‌ها و JSON روی دیسک محلی نوشته
  می‌شوند، اما دیتابیس durable، احراز هویت، مالکیت سازمانی، مجوزهای نقش‌محور و حذف خودکار نداریم.
- اگر API restart شود، فایل ممکن است باقی بماند اما شناسه و وضعیت در حافظه دیگر قابل بازیابی
  نباشد. به همین دلیل هنوز نباید قول نگهداری یا اشتراک امن گزارش بدهیم.
- PDF خروجی واقعی و قابل بازشدن است، اما پیش از ارسال به مشتری باید صفحات آن در محیط نهایی
  بصری بازبینی شوند و سیاست نگهداری فایل به توافق پایلوت وصل شود.
- هیچ دادهٔ شریک واقعی یا مجوز استفاده‌ای در این تست ساخته یا ادعا نشده است.

## تمرین توضیح شفاهی

«فایل را می‌گیریم، اول کیفیتش را کنترل می‌کنیم، بعد کمپین‌های داخل فایل را فهرست می‌کنیم. مدیر
خودش رویداد موردنظر را انتخاب می‌کند. گزارش یک شناسه دارد، در پس‌زمینه ساخته می‌شود و PDF آن
خلاصهٔ عددها و محدودیت‌ها را نشان می‌دهد. نتیجه فعلاً غربالگری مشاهده‌ای است؛ قبل از تصمیم
اجرایی، بررسی انسانی و در صورت نیاز آزمون کنترل‌شده لازم است.»
