# راهنمای ساده: چهار مسیر تصمیم مدیر

این بخش چهار انتخاب آشنای مدیر فروش را واضح می‌کند: «تکرار»، «اصلاح»، «آزمایش بیشتر» و
«توقف/کم‌اولویت‌کردن». اما نرم‌افزار نباید هر چهار گزینه را بی‌دلیل به‌عنوان پیشنهاد نشان دهد.

## معنی هر گزینه

### تکرار

برای گفتن «این کمپین را دوباره یا گسترده‌تر اجرا کن» به مقایسهٔ منصفانه، آزمون کنترل‌شده، هزینهٔ
اجرای کمپین و سود/حاشیهٔ تأییدشده نیاز داریم. دادهٔ فروش قبل و حین کمپین به‌تنهایی کافی نیست.
در MVP فعلی این گزینه به‌صورت خودکار پیشنهاد نمی‌شود.

### اصلاح

ممیزی مشاهده‌ای معمولاً نمی‌گوید دقیقاً قیمت، عمق تخفیف، مخاطب یا کانال باید چطور عوض شود. این
گزینه نیازمند بررسی عملیاتی مدیر و اطلاعات اجرای کمپین است؛ برنامهٔ فعلی نسخهٔ اصلاحی را حدس
نمی‌زند.

### آزمایش بیشتر

اگر یک رویداد برای آزمون کنترل‌شده نامزد باشد، یا شواهد ناقص باشند، پیشنهاد امن‌تر همین است.
آزمایش باید از قبل گروه مقایسه، معیار موفقیت، دورهٔ اندازه‌گیری و مسئول اجرا داشته باشد.

### توقف یا کم‌اولویت‌کردن

اگر غربالگری نتیجهٔ منفی بدهد، می‌توان کمپین را برای بازبینی انسانی کم‌اولویت کرد. این با دستور
خودکار برای توقف تفاوت دارد؛ موجودی، قیمت، فصل، توزیع و کیفیت داده ممکن است اختلاف را توضیح
دهند.

## منطق پیاده‌شده

`src/promoguard/insights/decision_support.py` نتیجهٔ typed ممیزی را به چهار گزینهٔ مدیریتی
ترجمه می‌کند:

- `candidate_for_controlled_test` ← «آزمایش بیشتر»؛ یعنی فقط ارزش طراحی آزمون دارد.
- `needs_more_evidence` ← «آزمایش/جمع‌آوری شواهد بیشتر»؛ هشدارها باید رفع شوند.
- `deprioritize_and_investigate` ← «کم‌اولویت‌کردن برای بازبینی انسانی»؛ نه توقف خودکار.
- «تکرار» همیشه تا وقتی آزمون تأییدشده و شواهد اقتصاد واحد فراهم نشده غیرفعال است.
- «اصلاح» به بررسی انسانی نیاز دارد و این گزارش اهرم تجاری را حدس نمی‌زند.

خروجی به API، داشبورد وب و خلاصهٔ Streamlit وصل شده است. خودِ تابع تصمیم‌یار هیچ عددی از فروش
یا سود دوباره محاسبه نمی‌کند؛ فقط توصیهٔ قبلی ممیزی را به زبان قابل‌فهم می‌گوید.

## تست‌های مهم

- رویداد مثبتِ غربالگری هیچ‌وقت به «تکرار» تبدیل نمی‌شود.
- نتیجهٔ منفی به «کم‌اولویت برای بازبینی انسانی» می‌رود، نه توقف قطعی.
- «اصلاح» نشان می‌دهد که بدون بررسی اهرم‌های تجاری پشتیبانی نمی‌شود.
- هر payload مرز مشاهده‌ای و غیرقطعی بودن تصمیم را حفظ می‌کند.

## پاسخ کوتاه به مدیر

«PromoGuard تصمیم نهایی را به‌جای شما نمی‌گیرد. می‌گوید با شواهد فعلی کدام قدم مسئولانه‌تر است.
برای تکرار باید آزمون و اقتصاد واقعی داشته باشیم؛ برای نتیجهٔ منفی هم فقط کم‌اولویت‌کردن و
بررسی علت را پیشنهاد می‌کنیم، نه توقف خودکار.»
