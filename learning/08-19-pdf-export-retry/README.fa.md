# راهنمای فاز ۸٫۲٫۱۰: تلاش دوباره برای دریافت PDF

## مسئله چه بود؟

ساخت فایل گزارش ممکن است موقتاً با خطای سرور یا شبکه روبه‌رو شود. پیام خطا باید برای کاربر قابل دیدن باشد و بعد از آن بتواند دوباره تلاش کند، بدون اینکه نتیجهٔ نمایش‌داده‌شده با ورودی گزارش عوض شود.

## چه چیزی آزمایش شد؟

تست مرورگر دو پاسخ شبیه‌سازی‌شده می‌سازد: بار اول سرور خطای موقت می‌دهد، بار دوم PDF برمی‌گرداند. تست کنترل می‌کند که خطا دیده شود، دکمه دوباره فعال شود، خطا پس از موفقیت پاک شود، و هر دو درخواست PDF دقیقاً همان متن ورودی‌ای را بفرستند که نتیجهٔ صفحه از آن ساخته شده است.

## این تست چه چیزی را ثابت نمی‌کند؟

پاسخ‌های سرویس در این تست ساختگی‌اند. تست، درستی endpoint واقعی، اتصال شبکهٔ مشتری، کیفیت PDF در دستگاه‌های مختلف یا مفید بودن تصمیم اقتصادی را اثبات نمی‌کند. تست API و دادهٔ مجاز شرکت همچنان لازم‌اند.

## اجرای تست

از پوشهٔ `frontend`:

```powershell
npx playwright test e2e/optimization-report.spec.ts --workers=1
```

این تست تمرکزش روی یک مسیر ساده است: خطای قابل فهم، امکان تلاش دوباره، و حفظ همان ورودی بررسی‌شده.
